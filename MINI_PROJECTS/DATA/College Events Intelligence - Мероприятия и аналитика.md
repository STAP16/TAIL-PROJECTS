# College Events Intelligence

**Направление:** Data & Analytics
**Дополнительное направление:** AI & Agents
**Уровень сложности:** Средний
**Срок:** 2 недели

## Проблема

Информация о мероприятиях колледжа может существовать в разных форматах и источниках: публикации, объявления, сообщения, документы, страницы сайта.

Из-за этого сложно получить единую картину: какие мероприятия уже прошли, что запланировано, какие направления активности преобладают, в какие периоды календарь перегружен, какие события относятся к конкретным студентам или направлениям, как меняется активность колледжа со временем.

Отдельная проблема — большая часть информации изначально существует в виде обычного текста, а не структурированных данных.

## Задача

Создать систему, которая собирает информацию о мероприятиях колледжа, преобразует её в структурированные данные с помощью AI и позволяет анализировать календарь активности.

## Описание

College Events Intelligence работает как Data Pipeline:

`Источник → Сбор → AI Extraction → Нормализация → Events Dataset → Calendar → Analytics`

На вход система может получать публикацию вроде:

> «18 октября в 15:00 в актовом зале состоится межрегиональный этап чемпионата. К участию приглашаются студенты...»

AI должен преобразовать её в структуру: название, дата, время, место, категория, направление, организатор, целевая аудитория, формат, статус, ссылка на источник.

После накопления данных формируется единый dataset мероприятий. На его основе можно анализировать: количество мероприятий по месяцам, распределение по категориям, активность по направлениям, наиболее загруженные недели, будущие и прошедшие события, динамику количества мероприятий, пересечения по времени.

**Главная идея проекта:** превратить поток неструктурированной информации о мероприятиях в данные, на основании которых можно анализировать жизнь колледжа.

## Минимальные требования

- работа минимум с несколькими источниками или подготовленными потоками данных;
- сохранение первоисточника;
- AI-извлечение информации из обычного текста;
- единая структура события;
- хранение событий;
- разделение будущих и прошедших мероприятий;
- календарное представление;
- фильтрация минимум по дате и категории;
- базовая аналитика;
- защита от неконтролируемого дублирования одинаковых событий.

## Возможное развитие

**Level 2 — Event Classification.** Добавить более подробную классификацию:
- образование · технологии · спорт · культура · карьера · конкурсы · внутренние мероприятия;
- направления: AI · Data · Robotics · Programming · Design · Business.

**Level 3 — AI Event Analyst.** Поверх dataset появляется AI-аналитик:
- «Какие технологические мероприятия прошли в этом месяце?»
- «Какая неделя сентября самая загруженная?»
- «Какие направления мероприятий встречаются чаще всего?»
- «Что запланировано на следующую неделю?»

**Level 4 — Calendar Intelligence.** Анализ календарной нагрузки: количество событий по дням, загруженность недели, пересечения по времени, дни без мероприятий, распределение активности по месяцам. Система может отмечать: «Перегруженная неделя» или «В пятницу одновременно проходят три мероприятия для одной аудитории участников».

**Level 5 — Campus Events Web Interface.** Связать Data-проект с MiniProject из трека Web Development — [[Campus Events - Веб интерфейс мероприятия колледжа|Campus Events]]. College Events Intelligence становится data/backend-контуром, а Campus Events — пользовательским интерфейсом. Связка: `Sources → College Events Intelligence → Structured Events Dataset → Events API / Data Interface → Campus Events → Student`.

**Level 6 — Personal Events.** Студент выбирает интересующие направления и получает релевантные события. Например: AI & Agents / Robotics / Career → «Рекомендуем вам».

**Level 7 — POLY Integration.** Events Dataset становится источником актуальных данных для [[POLY - AI ассистент|POLY]]. Пользователь спрашивает «Какие мероприятия будут завтра?», «Есть ли на этой неделе что-нибудь по AI?», «Когда следующий хакатон в колледже?» — POLY получает ответ из College Events Intelligence, а не из общих знаний модели.

## Оборудование и инструменты

Специальное оборудование не требуется. Нужны компьютер, доступ к выбранным источникам информации, AI-модель/API и инструменты для работы с данными. Конкретный инженерный стек заранее не задаётся.

## Что предстоит изучить

- сбор данных;
- работа с неструктурированным текстом;
- LLM Extraction;
- Structured Output;
- нормализация данных;
- проектирование Events Dataset;
- работа с датами и временем;
- дедупликация;
- классификация;
- календарная аналитика;
- построение Data Pipeline;
- работа AI поверх собственной базы;
- взаимодействие между Data-системой и Web-продуктом.

**Особенно важная концепция:** одни и те же данные могут использоваться несколькими продуктами. College Events Intelligence создаёт единый информационный контур, а Campus Events и POLY становятся потребителями этих данных.

## Полученные навыки

Data Collection, Data Engineering, Data Analytics, LLM Extraction, AI Classification, проектирование Data Pipeline, работа с календарными данными, аналитические метрики, интеграция между сервисами и AI-assisted development. Первый опыт проектирования системы, которая может стать источником данных для других продуктов.

## Результат

Работающий College Events Intelligence, который собирает информацию о мероприятиях колледжа, структурирует её с помощью AI и позволяет анализировать календарь активности. При реализации Level 5 система также предоставляет данные веб-продукту Campus Events.

## Критерии готовности

Проект считается завершённым, если:
- события поступают минимум из нескольких источников;
- AI корректно извлекает основные характеристики мероприятия;
- события приводятся к единой структуре;
- сохраняется первоисточник;
- доступны будущие и прошедшие мероприятия;
- работает календарное представление;
- доступны базовые фильтры;
- существует хотя бы несколько аналитических показателей;
- одинаковые события не создают бесконтрольные дубликаты;
- участник способен объяснить путь данных от исходной публикации до аналитики.

Для Level 5 дополнительно:
- существует стабильный интерфейс получения событий;
- Campus Events способен использовать эти данные;
- изменения в Events Dataset отображаются в Web-интерфейсе без ручного дублирования данных.

## Demo Day

Показать полный путь одного мероприятия: `Публикация → AI Extraction → структурированная запись → Events Dataset → Calendar → Analytics`. Затем открыть Campus Events и показать то же самое событие уже глазами студента. Финальная демонстрация показывает главную архитектурную идею: одни данные → аналитика для колледжа → интерфейс для студентов → потенциально POLY.
