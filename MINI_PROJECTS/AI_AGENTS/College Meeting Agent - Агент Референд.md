# College Meeting Agent

**Направление:** AI & Agents
**Дополнительные направления:** Memory · Structured Extraction · AI Automation
**Уровень сложности:** Средний
**Срок:** 2 недели

## Проблема

После рабочих встреч, собраний и обсуждений важная информация часто остаётся внутри длинной переписки, заметок или расшифровки разговора.

Через неделю становится сложно быстро восстановить:

- какие решения были приняты;
- какие задачи появились;
- кто отвечает за выполнение;
- какие сроки обсуждались;
- какие вопросы остались открыты;
- что было обещано на предыдущей встрече.

Особенно проблема проявляется при регулярных встречах: каждая новая встреча существует отдельно от предыдущих, а участникам приходится самостоятельно восстанавливать контекст.

## Задача

Создать AI-агента, который превращает транскрипт встречи в структурированный результат и способен сохранять контекст между последовательными встречами.

Агент должен не просто сделать краткое summary, а выделить **состояние работы после встречи**.

Например:

- Решения
- Задачи
- Ответственные
- Сроки
- Открытые вопросы
- Вопросы для следующей встречи

## Описание

На вход агент получает текстовую расшифровку встречи.

Первый pipeline:

```
Transcript → AI Extraction → Structured Meeting Record
```

Из разговора система формирует структурированную запись.

Например:

- Решение: запустить тестовый набор MINILAB в сентябре.
- Задача: подготовить наборную страницу.
- Ответственный: Степан.
- Срок: 25 августа.
- Открытый вопрос: количество наставников.

Но главная инженерная часть начинается со второй встречи.

В систему поступает новый транскрипт:

```
Meeting #1 → Memory → Meeting #2
```

Теперь агент должен уметь сопоставлять новый разговор с предыдущим состоянием.

Например:

- Что из прошлых задач было закрыто?
- Какие задачи перенесли?
- Какие решения изменились?
- Какие вопросы снова обсуждаются?
- Появились ли новые обязательства?

Таким образом агент начинает работать не с одной встречей, а с историей процесса.

## Минимальные требования

- загрузка транскрипта встречи;
- сохранение встречи;
- генерация краткого summary;
- извлечение решений;
- извлечение задач;
- выделение ответственных, если они указаны;
- извлечение сроков;
- выделение открытых вопросов;
- структурированный формат результата;
- просмотр истории обработанных встреч;
- сохранение исходного транскрипта.

Для MVP достаточно качественно обрабатывать одну встречу.

## Возможное развитие

### Level 2 — Meeting Memory

Связать несколько последовательных встреч.

Перед анализом новой встречи агент получает структурированное состояние предыдущей.

```
Previous Tasks → New Transcript → Updated Tasks
```

Теперь можно спрашивать:

- «Что осталось с прошлого собрания?»
- «Какие задачи закрыли?»
- «Какие сроки перенесли?»

Это знакомит участника с разницей между:

> историей сообщений и структурированной памятью системы.

### Level 3 — Task State

Добавить жизненный цикл поручений:

`OPEN → IN PROGRESS → DONE → CANCELLED`

Если на новой встрече участник говорит:

> «Страницу набора закончили».

агент должен сопоставить утверждение с существующей задачей и предложить изменить её состояние.

### Level 4 — Contradiction Detection

Агент сравнивает новые решения со старыми.

Например:

- Встреча #1: запуск назначен на 10 сентября.
- Встреча #2: решили запускать 17 сентября.

Агент отмечает:

> Изменение решения: дата запуска перенесена с 10 на 17 сентября.

Это уже существенно полезнее обычного summary.

### Level 5 — Meeting Tools

Добавить агенту инструменты:

- `get_previous_meeting()`
- `get_open_tasks()`
- `update_task()`
- `create_task()`
- `search_decisions()`

Тогда модель должна сама определить, какие данные ей необходимо получить для анализа новой встречи.

### Level 6 — Action Confirmation

Если агент предлагает изменить состояние реальной задачи:

> «Отметить задачу "Подготовить презентацию" как DONE?»

Пользователь подтверждает действие.

Так появляется Human-in-the-Loop.

### Level 7 — Meeting Preparation

Перед следующей встречей агент автоматически собирает briefing:

- что было решено в прошлый раз;
- 5 открытых задач;
- 2 просроченных;
- 3 вопроса без решения;
- что необходимо обсудить сегодня.

Теперь система работает до встречи, во время и после неё.

## 🔥 Потенциал реального внедрения

Это важная часть проекта.

College Meeting Agent не обязан заканчиваться на Demo Day MINILAB. Если прототип показывает хорошее качество, его можно продолжить уже как настоящий продукт основной [[TAIL - Overview|TAIL]].

### Собрания ПЦК

Агент может помогать:

расшифровка → решения → поручения → сроки → подготовка следующей встречи.

Не заменяя официальный документооборот, а выступая рабочим AI-инструментом сопровождения встреч.

### Проектные команды колледжа

Для регулярных рабочих встреч:

- Что решили?
- Кто что делает?
- Что заблокировано?
- Что изменилось за неделю?

### Основная TAIL

Здесь продукт можно начать использовать практически сразу.

Например после TAIL Daily / Weekly:

```
Transcript → Meeting Agent → Tasks → Decisions → Project Memory
```

И перед следующей встречей:

> «Какие вопросы мы должны сегодня закрыть?»

### Следующий уровень

В перспективе Meeting Agent может стать компонентом более крупной внутренней системы:

```
Meetings
   ↓
Meeting Agent
   ↓
Tasks / Decisions / Memory
   ↓
TAIL Project System
   ↓
AI Project Agent
```

То есть MiniProject постепенно эволюционирует из:

> «AI делает выжимку встречи»

в:

> «AI поддерживает состояние реального рабочего процесса между встречами».

## Оборудование и инструменты

Специальное оборудование не требуется.

Для MINILAB можно использовать заранее подготовленные или искусственные транскрипты встреч.

При работе с реальными встречами необходимо учитывать разрешение участников и правила работы с внутренней информацией.

Конкретный стек заранее не задаётся.

## Что предстоит изучить

- LLM Extraction;
- Structured Output;
- обработка длинного текста;
- сущности и состояния;
- meeting memory;
- context management;
- сопоставление информации между запусками;
- Tool Calling;
- Human-in-the-Loop;
- хранение истории;
- обновление состояния;
- границы между raw data и structured memory.

**Ключевая концепция:**

> Память агента — это не обязательно весь текст предыдущих разговоров. Часто полезнее сохранять структурированное состояние: решения → задачи → сроки → открытые вопросы.

## Полученные навыки

AI Engineering, Structured Extraction, State Management, Agent Memory, Context Engineering, Tool Calling, проектирование AI Workflow и работа с изменяющимся во времени состоянием.

## Результат

Работающий College Meeting Agent, который превращает транскрипт встречи в структурированный протокол рабочего состояния.

Базово:

```
Transcript → Summary + Decisions + Tasks + Deadlines + Open Questions
```

На более высоком уровне:

```
Previous Meeting + New Meeting → Updated Project State
```

## Критерии готовности

Проект готов, если:

- можно загрузить транскрипт;
- исходник сохраняется;
- агент выделяет решения;
- агент выделяет задачи;
- определяет ответственных и сроки там, где они явно присутствуют;
- формирует открытые вопросы;
- результат имеет стабильную структуру;
- можно открыть предыдущие встречи;
- агент не должен придумывать ответственного или срок, если этого нет в разговоре;
- участник способен объяснить разницу между транскриптом и памятью агента.

## Demo Day

Лучший сценарий — использовать две последовательные тестовые встречи.

На первой принимается несколько решений и ставятся задачи. Агент формирует состояние.

Затем загружается Meeting #2, где:

- одна задача выполнена;
- одна перенесена;
- изменилось одно решение;
- появился новый вопрос.

Агент должен показать, что изменилось между встречами.

#### Перспектива:

> Сегодня это MiniProject. Завтра этот же агент можно подключить к встречам проектной команды TAIL, затем протестировать на регулярных рабочих встречах, а при наличии реальной потребности — адаптировать для собраний ПЦК и других процессов колледжа.

Вот эта эволюция делает проект намного сильнее: участник понимает, что он строит не одноразовую учебную демку, а прототип потенциально настоящего продукта.
