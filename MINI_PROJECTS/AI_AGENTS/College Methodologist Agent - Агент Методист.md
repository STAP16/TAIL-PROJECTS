# College Methodologist Agent

Направление: **AI & Agents**

Дополнительные направления: **RAG · Knowledge Systems · AI Automation**

## Уровень сложности

Средний

## Срок

2 недели

## Проблема

В работе методиста используется большое количество информации: положения, регламенты, инструкции, методические материалы, учебные документы и другие внутренние источники колледжа.

Когда необходимо найти конкретное правило, срок или требование, сотруднику приходится самостоятельно определять нужный документ, открывать его и искать необходимый фрагмент.

При этом обычный универсальный AI-ассистент не знает внутреннюю документацию колледжа и может сформировать правдоподобный, но фактически неверный ответ.

## Задача

Создать специализированного AI-агента, который помогает методисту работать с определённой базой документов колледжа.

Агент должен находить релевантную информацию, отвечать на вопросы на основании доступных документов и показывать, из каких источников получен ответ.

Проект строится вокруг принципа:

> **Агент знает не всё. Он хорошо решает одну конкретную задачу в пределах предоставленной ему базы знаний.**

## Описание

College Methodologist Agent получает ограниченный набор документов по выбранному процессу колледжа.

Например:

- производственная практика;
- учебный процесс;
- методические требования;
- регламенты;
- положения;
- организация мероприятий.

Для MINILAB не требуется подключать всю документацию колледжа. Команда выбирает одну предметную область и небольшой безопасный набор документов.

Базовый контур:

**Документы → Knowledge Base → Retrieval → Context → LLM → Grounded Answer**

Методист может задавать вопросы естественным языком:

- «Какие документы нужны студенту для прохождения практики?»
- «Какие сроки указаны в положении?»
- «Что сказано о порядке защиты отчёта?»
- «Найди требования к оформлению документа».

Агент должен самостоятельно найти релевантные фрагменты и сформировать ответ.

Ключевое отличие от обычного чата с LLM:

> **Ответ должен быть основан на документах колледжа и проверяем пользователем.**

## Минимальные требования

- загрузка или подключение набора документов;
- сохранение документов в базе знаний;
- поиск релевантной информации;
- использование найденных фрагментов как контекста LLM;
- ответы на вопросы по базе;
- указание использованных источников;
- возможность открыть или определить исходный документ;
- корректная обработка вопросов, ответа на которые в базе нет;
- возможность добавлять новые документы без полной переделки системы.

Для MVP достаточно одной предметной области.

## Возможное развитие

### Level 2 — Semantic Retrieval

Добавить семантический поиск. Запрос пользователя не обязан содержать те же слова, что и документ.

Например:

> «Когда студент должен сдать итоговую работу?»

может находить фрагмент:

> «Отчётная документация предоставляется не позднее...»

Участник знакомится с embeddings, chunking и semantic retrieval.

### Level 3 — Source Grounding

Усилить проверяемость ответов. Для каждого существенного утверждения агент должен уметь показать: документ → раздел/фрагмент → использованная информация.

Пользователь должен иметь возможность самостоятельно проверить вывод AI.

Здесь участник сталкивается с одной из центральных проблем AI Engineering:

> **Хорошо звучащий ответ ещё не означает правильный ответ.**

### Level 4 — Document Comparison

Добавить инструмент сравнения документов.

Например:

> «Сравни редакцию положения 2025 и 2026 года».

Агент определяет: что добавилось; что удалилось; какие требования изменились; какие сроки изменились.

Это уже не обычный RAG-запрос, а отдельная операция над несколькими источниками.

### Level 5 — Methodologist Tools

Добавить агенту специализированные инструменты.

Например:

- `search_documents()`
- `read_document()`
- `compare_documents()`
- `find_deadlines()`
- `find_related_documents()`

Теперь модель должна определить, какое действие необходимо выполнить для решения задачи.

Контур становится:

**User Request → Agent → Tool Selection → Tool Result → Reasoning → Answer**

И здесь MiniProject впервые начинает превращаться из RAG-ассистента в полноценного агента.

### Level 6 — Structured Extraction

Научить агента извлекать из документов конкретные структуры.

Например, сроки:

| Действие         | Срок | Источник     |
| ---------------- | ---- | ------------ |
| Подача документа | …    | Положение №… |
| Защита           | …    | Регламент №… |

Или:

**Требование → Для кого → Когда → Основание**

Это позволяет использовать информацию уже не только в чате, но и в других системах.

### Level 7 — Change Monitoring

Система отслеживает появление новой версии документа. Если документ изменился:

> Обнаружена новая редакция положения.

Агент сравнивает версии и формирует краткий отчёт:

- изменены сроки подачи документов;
- добавлено новое требование;
- удалён пункт...

Так агент начинает не только отвечать на вопросы, но и следить за изменением своей предметной области.

## Оборудование и инструменты

Специальное оборудование не требуется.

Необходимы компьютер, AI-модель/API, безопасный набор документов и инструменты разработки.

Конкретный инженерный стек заранее не задаётся.

Для MINILAB используются только документы, которые разрешено передавать выбранной AI-инфраструктуре. Персональные и иные чувствительные данные в учебный dataset не включаются.

## Что предстоит изучить

- устройство специализированного AI-агента;
- контекст LLM;
- работа с документами;
- chunking;
- embeddings;
- semantic search;
- retrieval;
- RAG;
- grounding;
- citations;
- structured output;
- tool/function calling;
- обработка отсутствующей информации;
- границы ответственности агента;
- evaluation AI-ответов.

Особенно важны две концепции.

Первая:

> **LLM не является базой знаний.**

Документы существуют отдельно, система находит необходимую информацию и только после этого передаёт её модели.

Вторая:

> **Агент должен понимать границы своей компетенции.**

Если в предоставленных документах ответа нет, предпочтительный результат:

> «В доступной базе не удалось найти эту информацию».

а не правдоподобная догадка модели.

## Полученные навыки

RAG, Knowledge Systems, Retrieval, Context Engineering, Grounding, работа с LLM API, Tool Calling, Structured Output, AI Evaluation и проектирование специализированных AI-агентов.

Участник также получает опыт определения scope агента: что система должна уметь, какими данными располагает и какие действия ей разрешены.

## Результат

Работающий **College Methodologist Agent**, специализирующийся на одной выбранной области работы методиста и способный отвечать на вопросы по предоставленной документации с опорой на проверяемые источники.

Минимальный результат:

**вопрос → поиск → документ → релевантный контекст → AI → ответ + источник.**

## Критерии готовности

Проект считается завершённым, если:

- в систему можно добавить несколько документов;
- документы доступны для поиска;
- агент находит релевантные фрагменты;
- ответы формируются с использованием найденного контекста;
- пользователь видит источник ответа;
- новый документ можно добавить без переделки всей системы;
- агент корректно обрабатывает хотя бы часть вопросов, информации для которых в базе нет;
- участник способен объяснить разницу между знаниями LLM и Knowledge Base;
- участник способен объяснить полный путь запроса:

**Question → Retrieval → Context → LLM → Grounded Answer.**

## Demo Day

Для демонстрации готовится небольшой набор реальных или тестовых документов одной предметной области.

Сначала методист задаёт вопрос, ответ на который существует в базе.

Агент:

**находит документ → извлекает нужную информацию → формирует ответ → показывает источник.**

Затем задаётся вопрос, информации о котором в базе нет. Система должна продемонстрировать корректное поведение при недостатке данных.

Если реализованы дополнительные Levels, команда показывает работу Tools или сравнение двух версий документа.

Финальный вопрос участнику:

> «Почему методист должен доверять этому ответу?»

И ответ должен быть не:

> «Потому что его написал хороший AI».

А:

> «Потому что мы можем показать данные и документ, на основании которых система сформировала ответ».
