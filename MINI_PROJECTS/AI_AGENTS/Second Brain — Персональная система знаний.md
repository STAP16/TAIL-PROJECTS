## Проблема

В процессе обучения человек постоянно накапливает информацию: конспекты, заметки, документы, статьи, материалы по проектам, полезные ссылки и результаты исследований.

Со временем информации становится настолько много, что появляется другая проблема — **её сложно повторно использовать**.

Человек может помнить, что уже изучал определённую тему, но не помнить, где находится информация, в каком документе она записана, с каким проектом связана, какие выводы были сделаны и что изменилось с момента создания заметки.

Обычное файловое хранилище сохраняет информацию, но практически не помогает работать с накопленными знаниями.

## Задача

Создать первую версию собственной **Second Brain** — персональной AI-системы знаний.

Система должна позволять участнику сохранять собственные материалы, находить необходимую информацию и использовать AI для работы со своей базой знаний.

В отличие от большинства MiniProjects, Second Brain создаётся **не для условного пользователя**. Сам участник является пользователем своего продукта.

## Описание

Second Brain — персональное хранилище знаний с AI-слоем поверх него. В систему можно добавлять собственные заметки, учебные материалы, документы, исследования, информацию о проектах, статьи и другие текстовые материалы.

Базовая архитектурная идея:

**Knowledge Sources → Knowledge Store → Search → Context → AI**

Пользователь может спросить: «Что я изучал про REST API?», «Найди мои материалы про Arduino», «Что в моих заметках сказано про RAG?», «Какие идеи я сохранял для своего проекта?».

AI должен использовать **знания пользователя**, а не просто отвечать из собственных общих знаний. Участнику не выдаётся готовая архитектура — он должен самостоятельно определить, как хранить знания, как находить нужный контекст и как передавать его AI.

## Минимальные требования

Первая версия должна позволять:

- добавлять собственные текстовые материалы;
- сохранять их между запусками системы;
- просматривать накопленные материалы;
- выполнять поиск;
- задавать AI вопросы по собственной базе;
- находить релевантные материалы для вопроса;
- передавать найденный контекст модели;
- показывать, на какие собственные материалы опирается ответ;
- добавлять новые знания без пересоздания всей системы.

Главное требование:

> **Ответ Second Brain по персональным знаниям должен быть связан с реально существующей информацией в базе пользователя.**

## Возможное развитие

### Level 2 — Semantic Search

Добавить поиск не только по точному совпадению слов, но и по смыслу. Например, запрос «Как приложения общаются между собой?» может найти заметку «Основы REST API». Участник знакомится с embeddings и semantic retrieval.

### Level 3 — RAG

Построить полноценный Retrieval-Augmented Generation pipeline: **Question → Retrieval → Relevant Context → LLM → Grounded Answer**. Система выбирает только релевантные знания вместо передачи модели всей базы.

### Level 4 — Memory Manager

Second Brain начинает не только хранить информацию, но и **управлять знаниями**. При поступлении нового материала система анализирует:

> Это новое знание? Подобная информация уже существует? Новый материал дополняет существующее знание? Он противоречит старой информации? Нужно создать новую запись или обновить существующую?

AI может предложить действие **CREATE · UPDATE · LINK · IGNORE**. Критически важные изменения подтверждаются пользователем.

### Level 5 — Knowledge Graph

Добавить связи между знаниями. Второй Brain постепенно превращается из набора независимых документов в связанную систему знаний.

### Level 6 — External Sources

Подключить дополнительные источники: **Files · Notes · Web Articles · Telegram · YouTube summaries**. Новый источник должен приводить информацию к общей модели знаний Second Brain.

Важная архитектурная идея:

> **Источник информации и ядро системы — не одно и то же.**

### Level 7 — Personal Agents

Использовать Second Brain как **Knowledge Layer для персональных AI-агентов**.

```
                   SECOND BRAIN
                        │
            Personal Knowledge
                        │
        ┌───────────────┼───────────────┐
        ↓               ↓               ↓
 Research Agent     Study Agent     Project Agent
```

Research Agent использует прошлые исследования. Study Agent знает изученные материалы. Project Agent работает с контекстом конкретных проектов. Таким образом новый агент не начинает каждый диалог «с нуля».

## Оборудование и инструменты

Специальное оборудование не требуется. Необходимы компьютер, AI-модель/API, собственные материалы участника и инструменты разработки. Конкретный инженерный стек заранее не задаётся.

## Что предстоит изучить

- устройство LLM-приложений;
- контекст модели;
- хранение знаний;
- поиск информации;
- embeddings;
- semantic search;
- chunking;
- retrieval;
- RAG;
- grounding;
- работа с источниками;
- управление контекстом;
- долговременная память AI-систем;
- обновление знаний;
- архитектура AI-агентов.

Одна из главных концепций проекта:

> **Память AI-системы — это не просто история чата.**

Участнику предстоит разобраться, как построить отдельный слой знаний, который может существовать независимо от конкретного диалога и модели.

## Полученные навыки

AI Engineering, проектирование Knowledge Systems, RAG, Semantic Search, Context Engineering, работа с LLM API, управление знаниями, проектирование памяти AI-систем и AI-assisted development. На более высоких уровнях — Agent Architecture, Knowledge Graphs, Source Connectors и Memory Management.

## Результат

Персональная работающая **Second Brain v0.1**, содержащая реальные знания участника и позволяющая использовать AI для поиска и работы с ними. После двух недель участник должен иметь систему, которой **может продолжить пользоваться сам**, а не просто демонстрационный учебный проект.

## Критерии готовности

- пользователь может добавить собственный материал и он сохраняется;
- система умеет работать более чем с одним материалом;
- пользователь может выполнить поиск по знаниям;
- AI получает релевантный контекст из базы;
- можно задать вопрос по собственным материалам;
- ответ связан с реально существующими знаниями;
- пользователь может определить, какие материалы использовались;
- новые знания можно добавлять без пересоздания системы;
- участник способен объяснить весь путь: **Источник → Хранение → Поиск → Контекст → LLM → Ответ**.

## Demo Day

Second Brain лучше защищать **на собственных реальных данных**, а не на подготовленном демонстрационном dataset. Участник показывает свою базу знаний и добавляет новый материал.

Затем задаёт вопрос, ответ на который содержится в его знаниях: «Что я изучал по этой теме?» Система находит релевантные материалы и формирует ответ.

После этого задаётся вопрос, ответа на который **в базе нет**. Это позволяет проверить, понимает ли участник проблему grounding и способен ли Second Brain отличать собственные знания пользователя от общих знаний модели.

В завершение участник показывает архитектуру и выбирает, **какой следующий Level он реализовал бы после MINILAB**.
