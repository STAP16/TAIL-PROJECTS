# Student Navigator Agent

**Направление:** AI & Agents
**Дополнительные направления:** RAG · Agent Workflow · State Management · Tool Calling
**Уровень сложности:** Средний
**Срок:** 2 недели

## Проблема

Многие процессы колледжа понятны сотрудникам, которые работают с ними постоянно, но неочевидны студенту, который сталкивается с ними впервые.

Например:

- прохождение производственной практики;
- оформление определённых документов;
- участие в конкурсе или мероприятии;
- получение справки;
- выполнение административной процедуры.

Информация может существовать в документах и инструкциях, но студенту недостаточно просто найти нужный файл.

Ему необходимо понять: **Что конкретно мне делать сейчас?**

Даже если AI найдёт инструкцию на десять пунктов, студенту всё ещё приходится самостоятельно определять, какие пункты относятся именно к его ситуации и на каком этапе процесса он находится.

## Задача

Создать специализированного AI-агента, который сопровождает студента через один конкретный процесс колледжа от начала до результата.

Для MINILAB команда выбирает только один процесс. Например:

- **Student Practice Navigator** — агент вокруг прохождения практики;
- **Document Navigator** — для конкретной процедуры оформления документов.

### Главное ограничение

Student Navigator **не должен** становиться уменьшенной версией [[POLY - AI ассистент|POLY]].

POLY отвечает на широкий спектр вопросов о колледже. Navigator специализируется на одном процессе и помогает его пройти.

## Описание

Работа начинается не с AI, а с анализа выбранного процесса.

Участнику необходимо определить:

Начало → Этапы → Условия → Документы → Действия → Результат

Например, условный процесс может выглядеть так:

```
START
  ↓
Определить ситуацию студента
  ↓
Подготовить документы
  ↓
Передать документы
  ↓
Получить подтверждение
  ↓
Выполнить следующий этап
  ↓
FINISH
```

После этого поверх процесса строится AI-агент.

Студент может написать:

> «Мне нужно проходить практику. Я вообще не понимаю, с чего начать».

Агент сначала определяет ситуацию пользователя.

Затем показывает следующий релевантный шаг, а не выгружает всю инструкцию сразу.

Например:

> «Сначала нужно определить место прохождения практики. Оно у тебя уже есть?»

После ответа состояние меняется.

Базовый цикл:

```
User → Determine State → Find Rules → Determine Next Step → Response → Updated State
```

## Минимальные требования

- выбран один конкретный процесс колледжа;
- процесс разбит на этапы;
- определены возможные состояния;
- существует небольшая проверенная база знаний;
- агент отвечает с опорой на неё;
- агент определяет текущую ситуацию пользователя;
- учитывает уже выполненные этапы;
- предлагает следующий шаг;
- задаёт уточняющие вопросы при недостатке информации;
- сохраняет состояние прохождения процесса;
- пользователь может узнать свой текущий статус;
- информация из базы отделена от предположений модели.

Например:

> Текущий этап: подготовка документов\n> Выполнено: 2 из 5 шагов\n> Следующий шаг: получить ...

## Возможное развитие

### Level 2 — Process State

Формализовать процесс как набор состояний:

`NOT_STARTED → PREPARING → SUBMITTED → WAITING → COMPLETED`

Теперь состояние существует в программе, а не только в памяти LLM.

AI помогает определить переход, но система контролирует допустимые состояния.

Важный инженерный принцип:

> LLM понимает язык пользователя. Код контролирует состояние процесса.

### Level 3 — RAG & Sources

Подключить реальные инструкции и разрешённые документы выбранного процесса.

Pipeline:

```
Question → Retrieval → Relevant Rules → Agent → Next Step
```

Если студент спрашивает «Почему мне нужен этот документ?», агент показывает соответствующее основание.

Таким образом Navigator не только говорит **что** делать, но и способен объяснить **почему**.

### Level 4 — Student Checklist

На основании состояния автоматически формируется персональный checklist:

```
✓ Определено место практики
✓ Получена информация
○ Подготовить документ
○ Передать документ
○ Получить подтверждение
```

Разные исходные ситуации могут формировать разные маршруты.

### Level 5 — Tools

Добавить специализированные инструменты:

- `get_process_state()`
- `get_required_documents()`
- `search_instruction()`
- `complete_step()`
- `get_deadlines()`

Агент самостоятельно определяет, какой инструмент необходим.

### Level 6 — Safe Actions

Добавить действия во внешней системе (например, в тестовом контуре).

Агент предлагает: «Отметить этап "Подготовка документа" выполненным?»

Только после подтверждения пользователя вызывается соответствующий Tool.

```
Agent → Proposal → Human Confirmation → Action
```

### Level 7 — Proactive Navigator

Агент начинает учитывать сроки и состояние процесса.

### Level 8 — POLY Integration

Student Navigator не заменяет POLY. Он становится специализированной capability, которую в будущем можно подключить к [[POLY - AI ассистент|POLY]].

```
                 POLY
                   │
       «Помоги пройти практику»
                   │
                   ↓
        Student Navigator
                   │
          Process Runtime
                   │
        ┌──────────┼──────────┐
        ↓          ↓          ↓
     State       Tools       RAG
```

## 🔥 Потенциал реального внедрения

Проект хорошо подходит под принцип: **MINILAB создаёт прототип → TAIL может превратить его в production-компонент.**

После Demo Day можно выбрать наиболее удачный Navigator и проверить его вместе с сотрудником, отвечающим за соответствующий процесс.

В перспективе может существовать несколько Navigator:

- Practice Navigator
- Documents Navigator
- Events Navigator
- Admissions Navigator

А POLY определяет, когда передать пользователя специализированному агенту.

## Оборудование и инструменты

Специальное оборудование не требуется. Необходимы компьютер, AI-модель/API, описание выбранного процесса и разрешённые источники информации.

На этапе MINILAB реальные административные системы колледжа подключать не требуется. Все WRITE-действия можно реализовать в тестовом контуре.

**Ключевая концепция:**

> Ответить на вопрос и провести человека через процесс — две разные задачи. Navigator должен понимать: где пользователь находится сейчас → куда ему нужно попасть → какой следующий шаг допустим.

AI Engineering, Agent Workflows, State Management, RAG, Tool Calling, Context Engineering, Business Process Modeling, Human-in-the-Loop и проектирование специализированных AI-систем.

## Результат

Работающий Student Navigator Agent, сопровождающий студента через один выбранный процесс колледжа.

Минимальный цикл:

```
Situation → Current State → Rules → Next Step → Action → New State
```

Пользователь в любой момент должен понимать:

- Где я сейчас?
- Что уже сделано?
- Что мне делать дальше?

## Критерии готовности

Проект считается завершённым, если:

- выбран один конкретный процесс;
- процесс формально описан;
- определены его основные этапы;
- агент способен определить ситуацию пользователя;
- состояние сохраняется между сообщениями;
- выполненные этапы учитываются;
- агент определяет следующий шаг;
- при недостатке информации задаёт вопрос;
- ответы по правилам процесса опираются на предоставленные источники;
- невозможный переход между этапами не должен происходить только потому, что его попросил пользователь;
- участник способен объяснить, какая ответственность принадлежит LLM, а какая обычному коду.

## Demo Day

Лучше показать двух студентов с разными состояниями.

Первый начинает процесс с нуля. Второй уже находится в середине процесса. В конце участник показывает архитектуру:

```
LLM → Process State → RAG → Tools
```

и отвечает на главный вопрос проекта:

> Почему мы не попросили ChatGPT просто написать студенту инструкцию из десяти пунктов? Потому что задача Navigator — не рассказать о процессе. Задача Navigator — помочь конкретному человеку этот процесс **пройти**.
