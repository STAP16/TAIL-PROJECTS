# Career Quest

**Направление:** Game Development
**Дополнительные направления:** Game Design · Level Design · Storytelling · UX
**Уровень сложности:** Продвинутый
**Срок:** 2–3 недели

## Проблема

При выборе колледжа и специальности абитуриент сталкивается в основном с описаниями:

- какие дисциплины изучаются;
- какие компетенции формируются;
- кем можно работать после выпуска.

Но даже подробное описание плохо отвечает на гораздо более человеческий вопрос:

> «А что я вообще буду делать, если поступлю сюда?»

Название специальности и перечень дисциплин не дают ощущения самого пути. Career Quest предлагает не рассказывать об этом ещё одной страницей текста, а дать абитуриенту пройти этот путь самому.

## Задача

Создать короткую 2D top-down пиксельную игру, в которой абитуриент проходит небольшую сюжетную историю обучения по выбранной специальности. Игрок управляет персонажем и свободно перемещается по пиксельному колледжу: ходит по коридорам → заходит в аудитории → разговаривает с NPC → получает задания → выполняет квесты → продвигается по истории.

Одна специальность — одно короткое прохождение на 5–10 минут. За это время игрок должен получить представление:

- чему здесь учатся;
- какие задачи решают студенты;
- как меняется обучение со временем;
- какие проекты появляются;
- что происходит на практике;
- куда специальность может привести после выпуска.

> Главный принцип: **Не рассказать о специальности. Дать человеку немного её прожить.**

## Формат игры

Career Quest — именно бродилка, а не последовательность информационных экранов. Камера находится сверху, у игрока есть персонаж и пространство колледжа (аудитории, коридоры, лаборатории, кабинеты). Игрок самостоятельно исследует пространство и взаимодействует с преподавателями, студентами, компьютерами, лабораторным оборудованием, дверями, стендами, предметами и квестовыми объектами. Само перемещение по колледжу является частью опыта.

## Сюжет

Каждая специальность получает собственную небольшую историю, построенную по законченной арке:

**Поступление → Обучение → Проекты → Практика → Выпуск → Следующий путь**

### Начало (1 курс)

Игрок появляется у входа. Первый квест — найти аудиторию первого занятия. Преподаватель-NPC объясняет первую задачу. Вместо длинного рассказа игрок получает небольшое задание (например, для IT — восстановить порядок команд, найти ошибку в логике, собрать алгоритм). Мини-игра занимает 30–60 секунд и показывает характер деятельности.

### Продвижение по обучению (2 курс)

После нескольких заданий происходит временной переход: появляются новые помещения, NPC, более сложные задачи, проектная работа. Например, преподаватель сообщает о необходимости командного проекта → появляется Quest «Найти команду → получить требования → выполнить проектную задачу → показать результат».

### Практика

Следующий этап — временная смена локации (условная компания или рабочее пространство). Игроку дают ситуацию, связанную с реальной деятельностью специальности: «Вот задача. Попробуй решить».

### Финальный проект (Выпуск)

Игрок возвращается в знакомый колледж, где находятся NPC из прошлых этапов. Нужно завершить последнюю задачу и представить результат. После неё — `SPECIALTY COMPLETED` и показ возможных направлений дальнейшего развития (например, Backend Development, Data Engineering, AI Engineering и т.д. — в зависимости от специальности).

## MVP — минимальные требования

Для первой версии команда выбирает одну специальность. MVP должен содержать:

- управляемого персонажа;
- top-down пиксельную карту;
- минимум несколько помещений;
- взаимодействие с объектами;
- NPC;
- диалоговую систему;
- Quest System;
- минимум 3 сюжетных задания;
- хотя бы одну небольшую игровую механику внутри задания;
- сохранение текущего прогресса;
- начало и завершение истории;
- финальный экран специальности.

> Ключевое требование: **игрок должен играть большую часть прохождения, а не читать диалоговые окна.**

## Возможное развитие

### Level 2 — Quest System

Отделить квесты от игрового кода: Quest (ID, Title, Description, Objectives, Requirements, Status, Next Quest). Состояния: LOCKED → ACTIVE → COMPLETED. Работа с State и Progression Systems.

### Level 3 — Dialogue System

Полноценная система диалогов. NPC получает ID → Character → Dialogue → Conditions. Один и тот же персонаж может говорить разные вещи в зависимости от прогресса (Game State → NPC State → Dialogue).

### Level 4 — Specialty Content

Отделить игровой движок от содержания специальности (Game Core → Specialty → Story → Quests → NPC → Mini Games). Одна команда делает «Career Quest: специальность A», другая — «специальность B» без создания игры заново. Один из самых интересных вариантов развития.

### Level 5 — Multiple Specialties

На стартовом экране выбор специальности → своя сюжетная кампания (история, преподаватели, задания, мини-игры, навыки, практика, финал). Career Quest превращается в платформу профориентационных историй колледжа.

### Level 6 — Real College Content

Проверить игровой сценарий с представителями конкретной специальности: отражают ли задачи обучение, правильна ли последовательность, какие активности заменить, какие представления ошибочны. Переход: игровая идея → исследование → реальные требования → продукт.

### Level 7 — AI-assisted NPC

AI можно добавить к отдельным второстепенным NPC (Role + Allowed Knowledge + Game Context). Сюжетные персонажи и критичные Quest-события остаются детерминированными. **Game Logic контролирует игру, AI расширяет взаимодействие.**

### Level 8 — Player Choices

Небольшие решения (работать одному / попросить помощи / собрать команду) с разными последствиями. Одна и та же специальность проходится разными способами.

### Level 9 — Career Profile

В конце прохождения учёт действий игрока (технические задачи, данные, команда, исследовательские задания) → «тебе больше всего понравились задачи типа X». Не позиционируется как диагноз, а как направление для изучения.

## Потенциал для колледжа

Понятный пользователь — абитуриент, выбирающий специальность. Проект размещается на сайте или используется на дне открытых дверей:

> «Есть пять минут? Попробуй сам».

После прохождения: понравилась история → посмотреть страницу специальности → узнать условия поступления → задать вопрос. Career Quest должен оставаться коротким — его задача помочь человеку понять, интересно ли двигаться дальше, а не научить профессии.

## Что предстоит изучить

- основы GameDev;
- игровой цикл;
- Game State;
- управление персонажем;
- collision;
- Tile Maps;
- сцены;
- NPC;
- Dialogue System;
- Quest System;
- сохранение прогресса;
- Level Design;
- Pixel Art;
- Storytelling;
- игровые события;
- пользовательский сценарий;

При дальнейшем развитии: data-driven game architecture, AI NPC, LLM integration.

## Полученные навыки

Game Development, Game Design, Level Design, State Management, Quest Systems, Dialogue Systems, Pixel Art Pipeline, Storytelling и проектирование интерактивного пользовательского опыта. Особенно важен продуктовый навык — использовать игру как интерфейс для решения неигровой задачи.

## Результат

Работающий **Career Quest v0.1** — короткая 2D top-down пиксельная RPG, позволяющая абитуриенту пройти небольшую сюжетную версию обучения по одной специальности колледжа.

Минимальный цикл: **Explore → NPC → Quest → Action → Progress → New Stage → Graduation**

## Критерии готовности

Проект считается завершённым, если:

- существует законченная пиксельная локация колледжа;
- персонаж свободно перемещается по ней;
- есть NPC и взаимодействие;
- существует Quest System;
- история имеет начало и конец;
- минимум три задания требуют действий игрока;
- прохождение показывает разные этапы обучения;
- прогресс влияет на доступность событий;
- сюжет можно пройти за 5–10 минут;
- содержание выбранной специальности проверено на адекватность;
- игрок после прохождения способен своими словами объяснить, чем занимаются студенты этой специальности.

## Demo Day

Человеку дают управление без длинного объяснения: «Выбери специальность и попробуй прожить несколько лет обучения за пять минут». На экране пиксельный персонаж у входа в колледж. 1 курс → 2 курс → практика → выпуск. После прохождения игра показывает, какой путь прошёл игрок и куда специальность потенциально приводит.
