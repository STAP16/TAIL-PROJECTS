# Physical POLY

> **Направление:** Arduino & Robotics
> **Дополнительные направления:** AI & Agents · Voice Interfaces · Human–Robot Interaction
> **Уровень сложности:** Средний / продвинутый
> **Срок:** 2 недели для первой физической версии. Проект предполагает дальнейшее развитие вместе с самим POLY.

Физическое воплощение POLY — настольный AI-робот / интерактивный терминал, являющийся полноценным клиентом существующей системы POLY.

## Проблема

POLY существует как цифровой AI-ассистент колледжа: пользователь взаимодействует через сайт и чат. Но AI-система не обязана жить только внутри браузера. На мероприятии, выставке или в пространстве TAIL интереснее иметь физическую точку взаимодействия: человек подходит к устройству и просто спрашивает «POLY, что такое TAIL?» — устройство слышит, передаёт запрос существующей системе POLY и отвечает голосом.

**Задача проекта:** дать существующему программному продукту физическое воплощение.

## Задача

Создать физическую оболочку для POLY. Участник **не разрабатывает POLY заново** — основная AI-система, backend, знания и логика существуют независимо от робота. Команда делает новый интерфейс взаимодействия: `человек ↔ физический POLY ↔ существующий POLY Backend`.

**Базовый pipeline:** `Voice → Speech-to-Text → POLY → Text-to-Speech → Speaker`

Устройство дополнительно показывает своё состояние через экран, свет, движение или другие элементы.

## Описание

Минимальная конструкция: микрофон, динамик, контроллер, индикаторы, кнопка взаимодействия, корпус.

Более развитая версия: экран-лицо, анимированные глаза, LED-подсветка, сервоприводы, движение головы, датчик присутствия.

Самая важная часть — устройство должно быть **полноценным клиентом существующей AI-системы**, а не самостоятельной копией.

```
                 POLY
              AI SYSTEM
                  │
          ┌───────┴───────┐
          │               │
      Web Client     Physical POLY
                          │
                    ┌─────┼─────┐
                    ↓     ↓     ↓
                   Mic  Display Speaker
```

## Состояния Physical POLY

Физическая оболочка показывает пользователю, что происходит:

- **IDLE** — ожидание взаимодействия.
- **LISTENING** — пользователь говорит.
- **PROCESSING** — аудио обработано, POLY формирует ответ.
- **SPEAKING** — устройство воспроизводит ответ.
- **ERROR** — связь с системой или компонентом недоступна.

**State Machine:** `IDLE → LISTENING → PROCESSING → SPEAKING → IDLE`

Это позволяет участнику понять, почему поведение робота нельзя строить только на ответах LLM.

## Минимальные требования

Первая версия должна:

- принимать голос пользователя;
- преобразовывать речь в текст;
- отправлять запрос существующему POLY;
- получать ответ;
- преобразовывать его в речь;
- воспроизводить ответ через динамик;
- отображать текущее состояние устройства;
- иметь минимум один физический элемент взаимодействия;
- корректно обрабатывать отсутствие соединения или ошибку POLY;
- возвращаться в IDLE после завершения диалога;
- обращаться к одной основной системе (не к двум независимым копиям ассистента).

## Возможное развитие

- **Level 2 — POLY Face:** экран-лицо; состояние выражается глазами или анимацией (тема Human–Robot Interaction).
- **Level 3 — Movement:** сервоприводы (поворот головы, движения во время ответа), привязанные к состояниям: `Software State → Physical Behaviour`.
- **Level 4 — Presence Detection:** датчик присутствия; `IDLE → PERSON_DETECTED`, устройство становится интерактивным стендом.
- **Level 5 — Conversation:** поддержка последовательных реплик; появляются Session → Conversation History → Context.
- **Level 6 — Personality Through Hardware:** POLY Backend возвращает не только текст, но и `emotion`/`gesture`; устройство выбирает анимацию. `AI → Semantic State → Physical Representation`.
- **Level 7 — POLY Tools:** `Human → Physical POLY → POLY → Agent/Tools → TAIL Systems`; робот становится физической точкой доступа к экосистеме TAIL.
- **Level 8 — Physical POLY v2:** переработка корпуса (3D-модель → прототип → печать → электроника); пересечение Software Engineering + Electronics + Industrial Design + AI.

## Потенциал реального использования

- **Стенд TAIL:** постоянно рассказывает посетителям о проектах лаборатории.
- **День открытых дверей:** абитуриент взаимодействует с POLY напрямую («Какие специальности есть?», «Как попасть в лабораторию?»).
- **Выставки и конкурсы:** TAIL привозит собственного физического AI-ассистента вместо ноутбука с чатом.
- **Пространство колледжа:** в перспективе — информационный терминал колледжа.

## Связь с основной архитектурой POLY

**Physical POLY и POLY — не одно и то же. POLY — система, Physical POLY — клиент этой системы.**

```
                       POLY
                    Backend/API
                        │
             ┌──────────┼──────────┐
             ↓          ↓          ↓
          Website   Physical    Future Client
                     POLY
```

- Если робота отключить — POLY продолжает работать.
- Если заменить корпус — знания ассистента не исчезнут.
- Если обновить Knowledge Base POLY — новый контекст доступен и Web, и Physical POLY.

Отличный практический пример разделения ответственности компонентов системы.

## Оборудование и инструменты

ESP32/Arduino, Raspberry Pi или компьютер, микрофон, динамик, дисплей, LED, кнопка, сервоприводы, датчик присутствия, макетная плата, провода, источник питания, 3D-принтер. Также Speech-to-Text, Text-to-Speech и доступ к POLY API.

## Что предстоит изучить

Микроконтроллеры, Hardware/Software, API, Client–Server, Speech-to-Text, Text-to-Speech, аудиопотоки, State Machine, обработка ошибок, сервоприводы, дисплеи, Human–Robot Interaction, пользовательские сессии, интеграция существующего AI-продукта с новым интерфейсом.

**Главная концепция:** AI-продукт не равен своему интерфейсу. Одна AI-система может одновременно существовать на сайте, в приложении, в Telegram и внутри физического робота.

## Полученные навыки

Physical Computing, Arduino/ESP32, Hardware–Software Integration, API Integration, Client–Server Architecture, Speech Interfaces, State Machines, Human–Robot Interaction, AI-assisted development. Опыт работы не с проектом с нуля, а с уже существующей системой, к которой нужно спроектировать новый клиент.

## Результат

Работающий прототип **Physical POLY v0.1** — физическая оболочка существующего AI-ассистента колледжа.

Минимальный цикл: *Человек говорит → устройство слышит → POLY получает запрос → формирует ответ → устройство отвечает голосом.* Physical POLY визуально показывает своё состояние.

## Критерии готовности

Проект завершён, если:
- устройство принимает голос;
- речь преобразуется в текст;
- запрос отправляется в существующий POLY;
- используется настоящий ответ POLY;
- ответ воспроизводится голосом;
- существуют физически отображаемые состояния;
- устройство корректно возвращается в IDLE;
- ошибка соединения обрабатывается отдельно;
- Physical POLY не содержит собственной независимой копии знаний POLY;
- участник способен показать полный путь `Microphone → STT → Physical Client → POLY API → Response → TTS → Speaker`.

**Главный вопрос — «Где находится сам POLY?»**

> POLY находится не в роботе. Робот — лишь один из интерфейсов к системе POLY.

## Demo Day

На столе стоит Physical POLY без открытого ноутбука с чат-интерфейсом. Человек подходит, устройство замечает его или активируется кнопкой.

— POLY, что такое TAIL? → `LISTENING → PROCESSING → SPEAKING` → POLY отвечает.

Затем: — А как студенту попасть в TAIL? → снова настоящий запрос в POLY.

В конце открывается технический экран: `Voice → STT → POLY API → AI/Knowledge → Response → TTS → Hardware`.

Так Demo Day одновременно показывает эффектного физического робота и инженерную архитектуру за ним.
