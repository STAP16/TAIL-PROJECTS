# Voice Lab Controller

> **Направление:** Arduino & Robotics
> **Дополнительные направления:** AI & Agents · IoT · Physical Computing
> **Уровень сложности:** Средний
> **Срок:** 2 недели

Голосовое управление физическими устройствами лаборатории: естественный язык → безопасные команды реальному железу через AI Tool Calling.

## Проблема

В лаборатории постепенно появляется физическая инфраструктура: освещение, демонстрационные стенды, экраны, Arduino/ESP32-устройства, роботы, датчики, экспериментальные установки. Обычно каждое устройство имеет собственный способ управления. Voice Lab Controller исследует другой способ взаимодействия — превращение естественного человеческого языка в безопасные команды физическим устройствам.

Например, вместо поиска кнопки пользователь говорит:
- «Включи подсветку стенда POLY»;
- «Выключи всё демонстрационное оборудование».

Система должна понять намерение человека и выполнить соответствующее действие в физическом мире.

## Задача

Создать систему голосового управления несколькими физическими устройствами лаборатории.

**Базовая архитектура:** `Voice → Speech-to-Text → LLM → Tool Call → Controller → Physical Device`

Например:
- «Включи зелёную подсветку» → `action: set_light, state: on, mode: green` → Controller → LED

**Главная инженерная идея:**
> LLM понимает человека. Код контролирует физический мир.

LLM не должна напрямую управлять железом. AI может решить `set_light(on)`, но именно программная система проверяет существование устройства, разрешённость действия и физические команды контроллеру.

## Описание

Для первой версии достаточно собрать небольшой макет лаборатории: LED-подсветка, сервопривод, вентилятор, небольшой экран — представляя их реальными устройствами TAIL.

Система принимает голосовую команду, определяет действие и вызывает Tool: `set_light(on)`, `rotate_demo(angle)`, а для запросов состояния — `get_devices_state()`.

Полная цепочка уровней:
`Human → Microphone → Speech Recognition → LLM/Agent → Tool → Backend/Controller → ESP32/Arduino → Physical Device`

## Минимальные требования

- принимать голосовую команду;
- преобразовывать речь в текст;
- передавать команду AI;
- определять намерение пользователя;
- преобразовывать его в структурированное действие;
- поддерживать несколько различных команд;
- управлять минимум двумя физическими компонентами;
- получать состояние хотя бы части устройств;
- сообщать пользователю результат выполнения;
- корректно обрабатывать неизвестную команду;
- не выполнять действие, которого нет среди разрешённых возможностей.

## Возможное развитие

- **Level 2 — Natural Commands:** разные формулировки одного действия ведут к одному Tool Call (`set_light(on)`) — «Включи свет» / «Сделай здесь посветлее» / «Подсветку бы включить».
- **Level 3 — Device Registry:** реестр устройств и их capabilities вместо жёстко зашитой логики; добавление устройства = расширение системы.
- **Level 4 — Safe Actions:** риск-уровни; потенциально значимое действие (`shutdown_demo()`) требует подтверждения. Принцип `Intent → Validation → Confirmation → Execution`.
- **Level 5 — Multi-Step Commands:** составная цель (`prepare_lab()`) разворачивается в последовательность доступных действий. `Goal → Agent → Plan → Multiple Tools → Physical State`.
- **Level 6 — TAIL Device Integration:** подключение других MiniProjects Arduino Track (Talking Plant, Status Cube, Demo Stand) — общая точка управления, маленькая IoT-экосистема TAIL.
- **Level 7 — POLY Integration:** различие информационных запросов и физических действий POLY. `POLY → Tool Layer → Voice Lab Controller → ESP32 → Physical World`.
- **Level 8 — Lab Automation:** сценарии состояния лаборатории (DEMO MODE / CLOSED MODE); критичные физические устройства не должны автоматически подключаться.

## Потенциал развития в TAIL

Начало — микрофон + ESP32 + светодиоды + сервопривод на Demo Day. В перспективе — единый Device Registry и API физических устройств, POLY как интеллектуальный интерфейс физической лаборатории, а MiniProject становится инфраструктурным компонентом **TAIL IoT / Device Layer**, к которому подключаются новые устройства команд MINILAB.

## Оборудование и инструменты

Arduino или ESP32, компьютер, микрофон, LED/LED-лента, сервопривод, реле или другие безопасные низковольтные исполнительные компоненты, макетная плата, провода, AI API, Speech-to-Text. Для MINILAB лучше начинать с безопасных низковольтных макетов, а не управления сетевым оборудованием 220В. Конкретный стек заранее не задаётся.

## Что предстоит изучить

- основы микроконтроллеров, цифровые сигналы, датчики и исполнительные устройства;
- взаимодействие программы с физическим устройством;
- Speech-to-Text; LLM API;
- Structured Output; Tool Calling;
- Device API; IoT; состояния устройств;
- валидация команд; Human-in-the-Loop;
- разделение ответственности между AI и обычным кодом.

## Полученные навыки

Arduino/ESP32, Physical Computing, IoT, интеграция Hardware и Backend, Speech Interfaces, LLM Tool Calling, Agent Architecture, State Management, API и AI-assisted development. Главный опыт — соединение двух миров: Software ↔ Physical World.

## Результат

Работающий Voice Lab Controller, позволяющий управлять несколькими физическими устройствами естественными голосовыми командами. Цикл: Сказал → AI понял → система проверила → Tool вызван → устройство изменилось → результат подтверждён.

## Критерии готовности

Проект завершён, если:
- голос преобразуется в текст;
- система понимает несколько вариантов формулировок;
- AI формирует структурированное действие;
- существует минимум два управляемых физических компонента;
- действия выполняются через ограниченный набор Tools;
- можно получить состояние устройства;
- неизвестное действие не выполняется;
- ошибка устройства не превращается в ложное сообщение об успехе;
- участник способен показать весь путь команды;
- участник способен объяснить, почему LLM не получает прямого контроля над железом.

## Demo Day

На столе — небольшой макет TAIL Lab. Пользователь говорит «Включи подсветку» → свет включается; «Поверни демонстрационный модуль вправо» → работает сервопривод; «Что сейчас включено?» → Agent получает реальное состояние и отвечает; «Подготовь лабораторию к демонстрации» → система выполняет несколько разрешённых действий (при Multi-Step Level). Параллельно на экране — технический Trace `Voice → Text → Intent → Tool Call → Controller → Device`, чтобы зритель видел систему изнутри.
