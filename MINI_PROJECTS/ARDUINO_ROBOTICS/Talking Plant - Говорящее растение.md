# Talking Plant

> **Направление:** Arduino & Robotics
> **Дополнительные направления:** AI · Sensors · IoT · Physical Computing
> **Уровень сложности:** Начальный / средний
> **Срок:** 1–2 недели

Физическое растение с набором датчиков, которое определяет состояние окружающей среды и способно сообщать о нём человеку через AI. Датчики определяют реальность, код — состояние, AI отвечает за коммуникацию.

## Проблема

Растение не может сообщить человеку о своём состоянии. Недостаток воды, плохое освещение или неподходящая температура становятся заметны только по косвенным признакам — когда растение уже начинает выглядеть хуже. При этом состояние среды можно измерить обычными датчиками.

Главный принцип: AI не должен самостоятельно придумывать «Мне не хватает воды». Это должно определяться реальными показаниями датчиков. Задача AI — превратить сухие данные в понятную и живую коммуникацию.

## Задача

Создать физическое растение с набором датчиков, которое определяет состояние среды и способно сообщать о нём через AI.

**Базовая архитектура:** `Plant → Sensors → Measurements → State → LLM → Response`

Например:
- Влажность почвы: 14%
- Температура: 26°C
- Освещение: низкое
- State: NEEDS_WATER

LLM получает уже определённое состояние (не обязанность диагностировать растение) и превращает его в реплику в заданном характере.

**Главная инженерная идея:**
> Датчики определяют реальность. Код определяет состояние. AI отвечает за коммуникацию.

## Описание

В горшок устанавливается несколько датчиков (влажность почвы, температура, влажность воздуха, освещённость). Контроллер периодически получает измерения. Между датчиками и AI находится обычная программная логика:

`Sensors → Measurements → Rules → Plant State → LLM → Human`

Возможные состояния системы:
- **HAPPY** — всё нормально
- **NEEDS_WATER** — недостаточная влажность почвы
- **TOO_WET** — слишком высокая влажность
- **NEEDS_LIGHT** — недостаточное освещение
- **TOO_HOT** — слишком высокая температура
- **TOO_COLD** — слишком низкая температура

## Характер растения

Одна из главных фишек проекта — каждая команда может создать собственный характер Talking Plant. Фактическое состояние всегда одно и то же; меняется только способ коммуникации. Участник на практике видит разделение: **Data ≠ State ≠ Presentation**.

Примеры:
- **Спокойный:** «Влажность почвы немного снизилась. Когда будет возможность, полей меня».
- **Драматичный:** «14 процентов. Четырнадцать. Я просто оставлю эту информацию здесь».
- **Саркастичный:** «Отлично. Ты опять вспомнил обо мне только после уведомления».
- **Учёный:** «Влажность почвы снизилась ниже установленного порога. Рекомендую полив».

## Минимальные требования

Talking Plant должен:
- получать реальные данные минимум с двух датчиков;
- периодически обновлять измерения;
- преобразовывать измерения в определённое состояние;
- иметь несколько возможных состояний;
- передавать состояние AI;
- генерировать реплику растения;
- показывать или озвучивать её пользователю;
- иметь заданный характер;
- корректно работать при отсутствии AI-соединения;
- не использовать LLM как источник физических показателей.

Для первой версии достаточно: влажность почвы + освещение → State → AI Response.

## Возможное развитие

- **Level 2 — Voice:** `Sensors → State → LLM → Text-to-Speech → Speaker`. Растение действительно может заговорить при критическом изменении состояния («Так. У нас проблема с водой»). Система определяет, когда действительно необходимо обратиться к человеку.
- **Level 3 — Plant Face:** небольшой экран показывает состояние (`:)`, `:(`, `-_-` и простые анимированные глаза). Три канала: данные → визуальное состояние → характер → голос. Затрагивает Human–Machine Interaction.
- **Level 4 — History:** сохранение истории `Time → Soil → Light → Temperature → State`. Позволяет увидеть: когда поливали, как быстро сохнет почва, сколько времени без света. Пересечение с Data & Analytics.
- **Level 5 — Plant Memory:** память событий (`08:20 — NEEDS_WATER`, `09:10 — полили`, `09:30 — NORMAL`). `Current State + Previous State + Events → AI Response`. Простейшая форма памяти физического AI-устройства.
- **Level 6 — Conversation:** пользователь сам обращается к растению («Как ты себя чувствуешь?»). Растение становится небольшим физическим AI-агентом со своими Tools: `get_soil_moisture()`, `get_temperature()`, `get_light()`, `get_history()`.
- **Level 7 — Automatic Watering:** помпа для автоматического полива. Критично сохранить правильную архитектуру — не `LLM → «кажется надо полить» → Pump`, а `Sensor → Measurements → Deterministic Rules → Watering Decision → Safety Validation → Pump`. AI может объяснить решение, но запуск насоса контролируется обычным кодом с ограничениями по времени и объёму.
- **Level 8 — Plant Agent:** растение получает набор инструментов (`get_current_state()`, `get_history()`, `get_last_watering()`, `get_environment()`) и собственное состояние. Полноценный пример `Physical World → Digital State → Tools → AI Agent → Human`.

## Потенциал развития в TAIL

Talking Plant вряд ли нужен колледжу как серьёзная административная система — и это нормально. Его ценность — витринный экспериментальный проект TAIL, который легко понять человеку за несколько секунд. Отлично подходит для Demo Day, стенда TAIL, дней открытых дверей, выставок и демонстрации возможностей MINILAB. Может остаться жить в самой лаборатории как небольшой интерактивный объект.

## Связь с другими проектами TAIL

Talking Plant потенциально можно подключить к [[Voice Lab Controller - Голосовой контроллер лаборатории|Voice Lab Controller]]:

- «POLY, как там цветок?»
- Voice Lab Controller / POLY обращается: `get_plant_state()` и получает реальные данные.

`POLY → Tool Layer → Talking Plant → Soil / Light / Temperature`

Даже шуточный MiniProject становится ещё одним устройством общей TAIL Device Ecosystem.

## Оборудование и инструменты

Для базовой версии: Arduino или ESP32, настоящее растение, датчик влажности почвы, датчик освещённости, при необходимости датчик температуры/влажности, макетная плата, провода, компьютер, AI API.

Для следующих Levels: динамик, небольшой дисплей, микрофон, помпа, ёмкость для воды, дополнительные датчики, корпус/элементы на 3D-принтере. Для автоматического полива необходимо предусмотреть ограничение работы помпы и защиту электроники от воды.

## Что предстоит изучить

Arduino/ESP32, устройство датчиков, аналоговые и цифровые измерения, калибровку, сбор физических данных, состояния системы, deterministic rules, API, LLM, Prompt/Context Engineering, Text-to-Speech, IoT, историю событий, основы Agent Tools.

**Очень важный вопрос проекта:** откуда система знает, что цветку нужна вода?

Неправильный ответ: «Так решила нейросеть».

Правильный: «Это следует из измерений датчика и правил системы. AI только помогает сообщить это человеку».

## Полученные навыки

Physical Computing, Arduino/ESP32, Sensors, работа с реальными данными, State Machines, IoT, Hardware–Software Integration, LLM API, TTS и проектирование AI-функций поверх физических систем. Ещё один важный навык — понимание того, где AI действительно нужен, а где обычный алгоритм надёжнее.

## Результат

Работающий Talking Plant v0.1 — физическое растение, состояние которого определяется реальными датчиками, а AI позволяет растению выражать это состояние человеку в заданном характере.

**Минимальный pipeline:** `Plant → Sensors → Measurements → State → LLM → Message`

## Критерии готовности

Проект завершён, если:
- используются минимум два реальных датчика;
- значения можно посмотреть отдельно от AI;
- данные обновляются;
- определено несколько состояний растения;
- переход между состояниями зависит от измерений;
- LLM получает фактические данные/состояние;
- AI не придумывает физические показатели;
- растение генерирует разные реплики в рамках заданного характера;
- при отсутствии AI основные измерения продолжают работать;
- участник способен показать полный путь: `Physical World → Sensor → Data → Rules → State → AI → Human`.

## Demo Day

На столе — настоящее растение. На техническом экране: `Soil: 43%`, `Light: NORMAL`, `Temperature: 24°C`, `State: HAPPY`.

Человек спрашивает «Как дела?» → растение отвечает. Участник меняет одно из измеряемых условий или использует безопасный демонстрационный сценарий → состояние меняется на `NEEDS_WATER` → растение отвечает иначе. После демонстрации открывается архитектура и звучит главный вопрос: «Так где здесь AI?»

Ответ: AI не решает, хочет ли растение пить. Он позволяет физической системе говорить с человеком на человеческом языке.
