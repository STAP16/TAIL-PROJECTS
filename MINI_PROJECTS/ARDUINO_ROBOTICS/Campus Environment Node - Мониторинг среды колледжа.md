# Campus Environment Node

> **Направление:** Arduino & Robotics
> **Дополнительные направления:** IoT · Data & Analytics · Backend · AI
> **Уровень сложности:** Начальный / средний
> **Срок:** 1–2 недели

Компактное IoT-устройство для мониторинга параметров окружающей среды (температура, влажность, CO₂, освещённость, давление). Устройство периодически собирает данные с датчиков и передаёт их во внешнюю цифровую систему, превращая состояние помещения в телеметрию. Участник впервые строит полный путь данных: **физический мир → датчик → устройство → сеть → backend → база → аналитика**.

## Проблема

Температура, влажность, качество воздуха и освещённость постоянно меняются, но обычно человек замечает проблему субъективно («Здесь душно», «В кабинете очень жарко»). При этом эти параметры можно измерять постоянно и превращать состояние помещения в данные.

Главная ценность проекта для MINILAB — участник впервые строит полный путь данных:

**физический мир → датчик → устройство → сеть → backend → база → аналитика.**

## Задача

Создать **Campus Environment Node** — компактное IoT-устройство для мониторинга параметров окружающей среды.

В зависимости от оборудования Node может измерять:
- температуру;
- влажность воздуха;
- CO₂;
- освещённость;
- давление;
- другие доступные показатели.

Устройство периодически собирает данные и передаёт их в цифровую систему.

**Базовая архитектура:** `Environment → Sensors → ESP32 → Network → Backend → Storage`

Пример пакета данных:
```text
Node: ENG-LAB-01
Temperature: 24.7°C
Humidity: 42%
CO2: 714 ppm
Light: 380 lx
Timestamp: 12:41
```

Данные должны **покинуть микроконтроллер** и стать частью информационной системы — это главное отличие от обычной «Arduino-метеостанции».

## Описание

Первая версия может состоять из ESP32 и нескольких датчиков. Устройство раз в заданный промежуток времени:
- считывает показания;
- проверяет корректность измерений;
- формирует структурированный пакет данных;
- передаёт его по сети;
- backend принимает измерение;
- данные сохраняются вместе со временем и идентификатором Node.

Pipeline:
```text
Physical World → Sensors → ESP32 → Measurement → Network → API → Database
```

Environment Node — это **источник телеметрии**.

## Минимальные требования

Первая версия должна:
- использовать ESP32/другой подходящий контроллер;
- получать реальные данные минимум с двух датчиков;
- иметь уникальный идентификатор Node;
- периодически выполнять измерения;
- подключаться к сети;
- передавать измерения во внешнюю систему;
- сохранять время измерения;
- позволять посмотреть последние полученные данные;
- корректно обрабатывать временную потерю соединения;
- не генерировать значения через AI при отсутствии показаний датчика.

Минимальный pipeline: `Sensors → ESP32 → Network → API → Data`

## Возможное развитие

- **Level 2 — Local Display:** небольшой дисплей на Node. Устройство становится одновременно Sensor Node + Local Interface. Если backend недоступен, физические измерения можно увидеть непосредственно на устройстве.
- **Level 3 — Data Storage:** сохранение истории измерений. Появляются **time-series данные** (`12:00 → 22.8°C`, `13:00 → 23.5°C`). Участник сталкивается с вопросом: как хранить данные, которые поступают постоянно.
- **Level 4 — Dashboard:** простой интерфейс мониторинга с выбором периода (последний час / день / неделю). Естественный мост между Arduino & Robotics и Data & Analytics.
- **Level 5 — Events & Alerts:** правила с настроенными порогами (`CO2 > configured_limit → AIR_QUALITY_ALERT`). Пороги — часть конфигурации проекта, а не решения LLM. Работа с **событиями**: `Measurement → Rule → Event → Notification`.
- **Level 6 — Multiple Nodes:** несколько устройств, передающих данные в один backend. Появляется понятие **fleet of devices**.
- **Level 7 — Device Health:** наблюдение за самими устройствами (ONLINE/OFFLINE, время последней связи, качество сигнала, состояние датчиков, версия прошивки, заряд батареи). Принцип IoT: недостаточно собрать устройство — нужно понимать, работает ли оно после установки.
- **Level 8 — AI Analytics:** AI анализирует накопленные реальные данные (не создаёт их). `Database → Analytics → AI → Explanation`.
- **Level 9 — Environment Agent:** специализированный агент с Tools (`get_current_measurements()`, `get_node_status()`, `get_measurements_period()`, `compare_nodes()`, `get_alerts()`). `Human → Agent → Tools → Environment System → Data`.
- **Level 10 — POLY Integration:** Environment System как источник живых данных для POLY. `POLY → Environment Tool → Environment API → Backend → Database`. POLY получает доступ к **физическому состоянию окружающей среды**.
- **Level 11 — TAIL IoT Platform:** отделение общей инфраструктуры от конкретных датчиков. Общий контур Device Layer для физической инфраструктуры TAIL: `Physical Devices → Device Protocol/API → TAIL IoT → Device Registry → Events/Telemetry → TAIL Systems/POLY`. Первоначальный MiniProject становится прототипом Device Layer.

## AI в этом проекте

Здесь специально не нужно пытаться добавить LLM как можно раньше. Основная инженерная задача:
> научиться получать надёжные данные из физического мира и доставлять их в программную систему.

**Sensor** — измеряет. **ESP32** — собирает. **Backend** — принимает. **Database** — хранит. **Analytics** — считает. **AI** — помогает человеку работать с уже существующими данными.

Правильная архитектура: `Reality → Data → Software → Analytics → AI`, а не `Reality → AI → «кажется, здесь жарко».`

## Потенциал для колледжа

В отличие от некоторых экспериментальных Arduino MiniProjects, у Environment Node может появиться практическое продолжение. Но сначала команда должна доказать работоспособность на маленьком масштабе:
> один Node → одно помещение → несколько дней данных

после этого:
> несколько Nodes → несколько помещений

MINILAB не начинает сразу с обещания «оборудуем весь колледж датчиками» — сначала создаётся и проверяется инженерный прототип.

## Оборудование и инструменты

Для базовой версии: ESP32, датчик температуры/влажности, датчик освещённости, при необходимости CO₂-сенсор, небольшой дисплей, макетная плата, провода, питание, корпус.

Для нескольких Nodes: несколько ESP32, несколько наборов датчиков, сервер/backend, база данных, сеть Wi-Fi. Корпуса можно спроектировать и напечатать на 3D-принтере.

## Что предстоит изучить

ESP32, датчики, физические измерения, калибровку, Wi-Fi, HTTP/API, JSON, Backend, базы данных, timestamps, time-series данные, IoT, telemetry, polling, device identity, события, мониторинг устройств, Data Visualization, AI Analytics.

Главная инженерная цепочка проекта:
> Physical World → Measurement → Data → Network → Storage → Information

## Полученные навыки

Arduino/ESP32, Sensors, IoT, API Integration, Backend Integration, Telemetry, работа с временными данными, Data Collection, Hardware–Software Integration и основы мониторинга физических устройств. На следующих Levels: **Analytics → AI Tools → Agents → Distributed IoT Systems**.

## Результат

Работающий **Campus Environment Node v0.1**, который самостоятельно измеряет параметры окружающей среды и передаёт реальные данные во внешнюю цифровую систему.

Минимальный pipeline: `Environment → Sensors → ESP32 → Wi-Fi → API → Data`

## Критерии готовности

Проект считается завершённым, если:
- используются минимум два физических датчика;
- устройство получает реальные измерения;
- Node имеет собственный ID;
- ESP32 подключается к сети;
- данные передаются через API;
- каждое измерение связано со временем;
- данные можно посмотреть вне самого микроконтроллера;
- временное отсутствие backend не ломает работу устройства;
- система отличает отсутствие данных от реального нулевого значения;
- участник способен проследить конкретное измерение от датчика до цифровой системы.

Главное — участник может ответить: «Откуда взялось это число на dashboard?» — полностью:
> Физическая величина → датчик → измерение → ESP32 → сеть → API → backend → сохранённая запись → интерфейс.

## Demo Day

На столе стоит **Campus Environment Node**. Рядом открыт интерфейс с текущими показателями:
```text
NODE: TAIL-01
STATUS: ONLINE

Temperature     24.3°C
Humidity        41%
Light           426 lx

Last update     3 sec ago
```

Участник изменяет окружающее условие безопасным способом (например, закрывает датчик освещённости). Физический показатель меняется. Через несколько секунд: `Sensor → ESP32 → API → Backend → Dashboard` и новое значение появляется на экране.

Если реализован AI Level, в конце можно спросить: «Что происходило с освещённостью во время демонстрации?» AI получает накопленные измерения и объясняет изменение. Зритель видит весь путь: изменение в реальном мире превратилось в данные, прошло через созданную студентом систему и стало информацией, с которой может работать даже AI.
