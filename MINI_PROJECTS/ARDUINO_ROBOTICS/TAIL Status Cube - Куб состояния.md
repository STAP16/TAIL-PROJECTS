# TAIL Status Cube

> **Направление:** Arduino & Robotics
> **Дополнительные направления:** IoT · API Integration · Physical Computing · Data Visualization
> **Уровень сложности:** Начальный / средний
> **Срок:** 1–2 недели

Физический куб, подключённый к цифровым системам лаборатории и визуально отображающий их состояние. Главная идея проекта: **физическое устройство становится клиентом цифровой системы.**

## Проблема

Большая часть состояния цифровых систем существует только внутри экранов. Чтобы узнать, работает ли сервис, какое событие проходит сегодня или в каком состоянии находится проект, человеку необходимо открыть сайт, приложение или dashboard. Но некоторые данные можно сделать частью физического пространства лаборатории. Например, находящийся на столе объект может без открытия интерфейсов показывать: сегодня проходит Demo Day; POLY находится Online; лаборатория работает в режиме презентации; приближается важный дедлайн; один из сервисов недоступен.

**Задача:** превратить состояние цифровой системы в физический объект, который можно понять одним взглядом.

## Задача

Создать физический TAIL Status Cube, подключённый к цифровым системам лаборатории и способный визуально отображать их состояние. Куб получает данные через API и преобразует их в физическое представление: `цвет/свет → анимация → экран → символ → движение`.

**Базовая архитектура:** `TAIL System → API → Status Data → Controller → Physical Cube`

Например:
- `POLY: ONLINE`
- `Next event: DEMO DAY`
- `Projects: 4 ACTIVE`
- `Lab mode: NORMAL`

превращается в определённое состояние физического объекта.

**Главная идея проекта:** физическое устройство становится клиентом цифровой системы.

## Описание

Первая версия может представлять собой небольшой куб, корпус которого напечатан на 3D-принтере. Внутри: `ESP32 → LED → небольшой дисплей → питание`. Куб периодически обращается к API и получает актуальное состояние.

Например: `NORMAL`, `DEMO`, `EVENT`, `DEADLINE`, `ERROR`, `OFFLINE`. Каждому состоянию соответствует собственное физическое отображение. Участник должен спроектировать его так, чтобы человек понимал состояние без чтения технических логов:

- **NORMAL** — нейтральная индикация.
- **DEMO** — динамическая анимация.
- **EVENT** — отображается ближайшее событие.
- **DEADLINE** — показывается проект и оставшееся время.
- **ERROR** — устройство сигнализирует о проблеме.
- **OFFLINE** — отдельное состояние отсутствия связи.

```
Digital State → Status API → ESP32 → State Machine → Physical Representation
```

## Что именно может показывать Cube

Команда самостоятельно выбирает назначение первой версии. Варианты:
- **TAIL Lab Status:** NORMAL / DEMO / EVENT / OFFLINE;
- **Project Status:** ANALYSIS / DESIGN / DEVELOPMENT / TESTING / RELEASE;
- **состояние нескольких систем:** POLY — ONLINE, Website — ONLINE, Demo Stand — READY;
- **ближайшие события:** DEMO DAY через 2 дня.

Для MVP лучше выбрать один сценарий, а не пытаться вывести на куб всю информацию TAIL.

## Минимальные требования

Первая версия должна:
- иметь физический корпус;
- использовать микроконтроллер;
- иметь визуальную индикацию;
- поддерживать несколько состояний;
- получать хотя бы часть состояния из внешней цифровой системы;
- обращаться к API;
- периодически обновлять данные;
- преобразовывать полученные данные в физическое состояние;
- отдельно отображать отсутствие соединения;
- продолжать корректно работать при временной недоступности API.

**Минимальный pipeline:** `API → JSON → State → ESP32 → Visualization`

## Возможное развитие

### Level 2 — Multiple States
Увеличить количество состояний (NORMAL, DEMO, EVENT, DEADLINE, MAINTENANCE, ERROR, OFFLINE). Главная задача — не просто придумать разные анимации, а разработать понятный визуальный язык устройства. Человек должен постепенно научиться понимать Cube без приложения.

### Level 3 — Display
Добавить небольшой экран. Теперь Cube может не только показывать состояние, но и объяснять его (например: `DEMO DAY TODAY · 16:00` или `DEADLINE 2 DAYS`). Свет отвечает за быстрое восприятие состояния, экран — за детали.

### Level 4 — Live TAIL Data
Отказаться от подготовленных демонстрационных состояний. Cube получает реальные данные TAIL через `GET /status`, `GET /projects`, `GET /events`. Устройство самостоятельно обновляет состояние через заданный интервал. Это уже полноценная IoT-интеграция.

### Level 5 — Multiple Sides
Использовать физическую форму куба как часть интерфейса. Разные стороны посвящены разным областям (POLY, PROJECTS, EVENTS, LAB). Пользователь поворачивает Cube, датчик ориентации определяет положение устройства и переключает отображаемую область. Сам физический объект становится интерфейсом управления.

### Level 6 — Interactive Cube
Добавить взаимодействие: поворот → смена раздела; касание → подробности; двойное касание → следующее событие; встряхивание → возврат на главный экран. Проект начинает затрагивать Human–Computer Interaction без привычного экрана и мыши.

### Level 7 — Voice Lab Controller Integration
Подключить Cube к ранее созданному [[Voice Lab Controller - Голосовой контроллер лаборатории|Voice Lab Controller]]. Пользователь говорит «Переведи куб в режим Demo Day» → Voice Lab Controller вызывает `set_cube_mode(DEMO)`, или «Что показывает куб?» → `get_cube_state()`. Проекты разных участников начинают взаимодействовать друг с другом.

### Level 8 — POLY Integration
Cube можно предоставить POLY как физический Tool. Например: «POLY, покажи на кубе следующий дедлайн» → POLY получает информацию и вызывает действие устройства; или во время презентации «POLY, включи Demo Mode». Cube становится одним из физических output-устройств экосистемы [[POLY - AI ассистент|POLY]].

## Project Cube — второе направление развития

Вместо общего состояния лаборатории Cube можно превратить в физический индикатор жизненного цикла проекта TAIL: `АНАЛИЗИРУЙ → ПРОЕКТИРУЙ → ВОПЛОЩАЙ → TEST → RELEASE`. Команда начинает новый проект — Cube показывает ANALYSIS; проектирование завершено — DESIGN; началась реализация — BUILD; на Demo Day — RELEASE. Так физический объект начинает отражать рабочий цикл TAIL.

## Потенциал развития в TAIL

TAIL Status Cube — прежде всего инфраструктурный и дизайнерский эксперимент лаборатории. Он исследует область **Physical Interfaces for Software Systems**. Если эксперимент удачен, принцип применяется к другим устройствам: индикатор занятости оборудования, статус 3D-принтера, состояние Demo Stand, индикатор помещения, физический таймер мероприятия.

> Результат проекта — не только Cube, но и понимание, как цифровые состояния переносить в физическую среду.

## Оборудование и инструменты

Для базовой версии: ESP32; адресные LED; небольшой OLED/LCD-дисплей; макетная плата; провода; питание; корпус; 3D-принтер.

Для следующих Levels: акселерометр/гироскоп; сенсор касания; дополнительные дисплеи; динамик; аккумулятор.

Со стороны программной системы понадобится API, отдающий состояние в структурированном формате.

## Что предстоит изучить

Arduino/ESP32; Wi-Fi и сетевое взаимодействие микроконтроллера; HTTP/API; JSON; polling; State Machine; обработку сетевых ошибок; LED и дисплеи; датчики ориентации; IoT; физические интерфейсы; визуализацию данных; Hardware–Software Integration.

**Важная концепция проекта:** API предназначен не только для сайтов и мобильных приложений. Его клиентом может быть физическое устройство.

## Полученные навыки

Arduino/ESP32, IoT, API Integration, State Machines, Physical Computing, работа с дисплеями и LED, обработка сетевых состояний, Hardware–Software Integration и основы Physical UX. Отдельный навык — умение превращать абстрактные цифровые данные в понятное физическое представление.

## Результат

Работающий TAIL Status Cube v0.1, подключённый к цифровому источнику данных и отображающий его актуальное состояние в физическом пространстве.

**Минимальная цепочка:** `TAIL Data → API → ESP32 → State → Physical Visualization`

## Критерии готовности

Проект завершён, если:
- существует физический прототип Cube;
- устройство подключается к сети;
- получает данные из API;
- данные действительно влияют на физическое состояние;
- реализовано минимум три состояния;
- состояния визуально различимы;
- данные периодически обновляются;
- недоступность API имеет отдельное состояние;
- после восстановления соединения Cube самостоятельно возвращается к актуальным данным;
- участник способен объяснить полный путь `Source → API → Network → ESP32 → State Machine → Physical Output`.

## Demo Day

На столе находится TAIL Status Cube. На экране системы: `Lab Mode: NORMAL` → Cube показывает соответствующее состояние. Затем значение меняется на `Lab Mode: DEMO` → через API новое состояние получает Cube, и физический объект изменяется без перепрошивки или ручного переключения. После этого можно отключить API — Cube должен показать `OFFLINE`. Сервис возвращается — устройство автоматически восстанавливает актуальное состояние.

Если реализован интерактивный Level: участник переворачивает Cube стороной POLY вверх → `POLY · ONLINE`; переворачивает на EVENTS → `DEMO DAY · TODAY`.

> TAIL Status Cube — это не светящийся Arduino-куб. Это физический интерфейс к живому состоянию цифровой системы.
