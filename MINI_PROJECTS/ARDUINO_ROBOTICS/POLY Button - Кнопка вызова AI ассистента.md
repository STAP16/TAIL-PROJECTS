# POLY Button

> **Направление:** Arduino & Robotics
> **Дополнительные направления:** AI · Voice Interfaces · Accessibility
> **Уровень сложности:** Начальный
> **Срок:** 1 неделя

Физическая кнопка быстрого голосового обращения к POLY или другому AI-агенту. Интерфейс к AI необязательно должен быть экраном.

**Базовый сценарий:** *нажал → сказал → получил ответ.*

## Проблема

Основной способ взаимодействия с AI-ассистентами сегодня — открыть устройство, найти приложение, открыть чат и написать или продиктовать запрос. Но для некоторых сценариев гораздо естественнее одно физическое действие. Особенно это важно в Assistive Tech, где обычная клавиатура, мышь или сенсорный экран могут быть неудобны или недоступны.

**Вопрос:** можно ли свести взаимодействие с AI-ассистентом к одному физическому действию?

## Задача

Создать **POLY Button** — физическую кнопку быстрого голосового обращения к POLY или другому AI-агенту.

**Базовая архитектура:** `Button → Audio → Speech-to-Text → POLY → Text-to-Speech → Speaker`

## Главная идея

Кнопка сама по себе почти ничего не делает — она является **физическим интерфейсом к программной системе**. Это позволяет показать, что AI-продукт может существовать не только внутри браузера.

```
Human → Physical Input → Device → Voice Interface → AI Agent → Digital Action → Human Feedback
```

## Состояния POLY Button

- **IDLE** — ожидание взаимодействия.
- **LISTENING** — устройство принимает голосовой запрос.
- **PROCESSING** — запись преобразуется в текст и отправляется POLY.
- **SPEAKING** — ответ воспроизводится.
- **ERROR** — ошибка соединения или агента.

**State Machine:** `IDLE → LISTENING → PROCESSING → SPEAKING → IDLE`

Ключевой дизайн-вопрос: как пользователь без экрана поймёт, что сейчас происходит? Можно использовать световую индикацию, звуки, вибрацию или небольшой дисплей. Команда проектирует не только электронику, но и **физический UX**.

## Минимальные требования

POLY Button должен:
- иметь физическую кнопку;
- определять нажатие;
- иметь несколько состояний работы;
- давать пользователю обратную связь;
- принимать голосовой запрос;
- преобразовывать речь в текст;
- отправлять запрос внешнему AI-ассистенту;
- получать ответ;
- возвращать его пользователю;
- корректно обрабатывать недоступность сети или агента;
- самостоятельно возвращаться в режим ожидания.

**Минимальный pipeline:** `Button → Voice → POLY → Response`

## Возможное развитие

- **Level 2 — Voice Response:** полностью убрать необходимость смотреть на экран; добавляется TTS: `POLY Response → TTS → Speaker`. Полный цикл становится голосовым. Это уже полноценный screenless-интерфейс.
- **Level 3 — Physical POLY:** подключить POLY Button к **Physical POLY**; кнопка становится одним из способов активации физической оболочки: `POLY Button → Physical POLY → POLY Core`.
- **Level 4 — Agent Button:** отвязать устройство от конкретного POLY; кнопка обращается к разным агентам через `Agent Gateway` (POLY, Meeting Agent, Second Brain и др.). Устройство становится универсальной физической точкой входа к агентам.
- **Level 5 — Multiple Actions:** короткое нажатие → POLY; двойное → другой агент; удержание → специальное действие. Здесь accessibility-задача поиска баланса между универсальностью и простотой.
- **Level 6 — Configurable Button:** назначение кнопки настраивается в интерфейсе; физическое устройство перестаёт быть жёстко связано с одной функцией.
- **Level 7 — Multiple Buttons:** небольшая физическая панель (POLY / MEETING / NOTE / HELP); каждая кнопка вызывает свой сценарий.

## Accessibility-сценарий

Вместо `разблокировать устройство → открыть браузер → найти сервис → выбрать поле → набрать текст → отправить` можно спроектировать **одно большое физическое действие → голос**. Сама кнопка может быть адаптирована: увеличенный размер, малая сила нажатия, удобное расположение, тактильно различимая поверхность, крепление рядом с пользователем. Программная функция остаётся той же — меняется **способ доступа к ней**.

## Инженерный вопрос

> **Где заканчивается физическое устройство и начинается AI-система?**

ESP32 не обязан запускать POLY. Его задача — **зафиксировать действие → передать событие**. Дальше компьютер или backend выполняет `Audio → STT → Agent → TTS`. Это хороший первый контакт с **разделением ответственности между компонентами системы**.

```
[ Physical Layer ]        [ Software Layer ]
Button → Controller       Voice Runtime → Agent → Response
```

## Что предстоит изучить

Arduino/ESP32, кнопки и физический ввод, события, State Machine, debounce, микрофон, аудио, Speech-to-Text, Text-to-Speech, API, сетевое взаимодействие, AI Agents, физическая обратная связь, основы Accessibility, Human–Computer Interaction.

## Полученные навыки

Physical Computing, Arduino/ESP32, Voice Interfaces, API Integration, STT/TTS, State Machines, Hardware–Software Integration и базовые принципы Accessibility. Основной навык проекта — **умение проектировать альтернативный интерфейс к уже существующей цифровой возможности**.

## Результат

Работающий **POLY Button v0.1** — физическое устройство, позволяющее одним нажатием начать голосовое взаимодействие с POLY.

Базовый цикл: `Press → Listen → Understand → Ask POLY → Speak → Ready`

При дальнейшем развитии: `Physical Button → Agent Gateway → выбранный AI Agent`

## Критерии готовности

Проект завершён, если:
- физическая кнопка действительно является началом взаимодействия;
- система различает состояния IDLE / LISTENING / PROCESSING / RESPONSE;
- пользователь получает понятную обратную связь;
- голос преобразуется в запрос;
- запрос действительно поступает POLY;
- ответ возвращается пользователю;
- ошибка соединения обрабатывается отдельно;
- повторное взаимодействие возможно без перезапуска системы;
- участник способен объяснить весь путь от физического нажатия до ответа AI.

## Demo Day

На столе большая кнопка. Без клавиатуры. Пользователь нажимает её → `LISTENING` → говорит «Расскажи, что такое TAIL» → `PROCESSING` → POLY получает запрос → `SPEAKING` → пользователь слышит ответ → `READY`. Затем демонстрируется второй сценарий: та же кнопка подключается к другому агенту.

> **POLY Button — это не кнопка с AI внутри. Это физический интерфейс, через который человек получает простой доступ к цифровым агентам.**
