# AI Drawing Robot

## Направление

**Arduino & Robotics**

Дополнительные направления: **AI · Computer Graphics · Motion Control · Physical Computing**

## Уровень сложности

Средний / продвинутый

## Срок

2 недели для базовой версии

## Проблема

AI отлично работает с цифровым контентом: может понимать описание, генерировать изображение, анализировать его и преобразовывать информацию.

Но между:

> **«Нарисуй ракету»**

и реальным движением карандаша по бумаге лежит большая инженерная цепочка.

Робот не понимает, что такое «ракета».

Мотор не понимает изображение.

Мотор понимает только конкретные команды движения.

Поэтому возникает задача:

> **Как превратить человеческую идею в последовательность точных физических действий машины?**

---

# Задача

Создать робота, способного получать описание или цифровой рисунок и воспроизводить его на физическом носителе.

Например:

> «Нарисуй минималистичного робота».

Система должна пройти путь:

**Human Request → AI → Drawing Representation → Path Planning → Coordinates → Motion Controller → Motors → Drawing**

AI отвечает за интерпретацию идеи и подготовку цифрового представления.

Программная система отвечает за преобразование рисунка в допустимые траектории.

Контроллер отвечает за точное физическое движение.

---

# Описание

Физически AI Drawing Robot можно построить как небольшой **XY-плоттер**.

Есть две оси:

**X** — движение влево/вправо.

**Y** — движение вперёд/назад.

И отдельный механизм:

**Pen Up / Pen Down**

для поднятия и опускания карандаша.

Базовый принцип:

```text
             Y
             ↑
             │
             │
             └────────→ X
```

Чтобы нарисовать квадрат, система может получить последовательность точек:

```text
(20,20)
(60,20)
(60,60)
(20,60)
(20,20)
```

Контроллер последовательно перемещает инструмент между координатами.

Таким образом участник сначала должен научить машину **рисовать без всякого AI**.

И только после того, как Motion System работает надёжно, сверху добавляется интеллектуальный слой.

Это важный принцип проекта:

> **Сначала машина должна научиться рисовать то, что ей точно сказали. Только потом AI получает возможность решать, что ей сказать.**

---

# Минимальные требования

Первая версия должна:

* иметь физический механизм перемещения;
* управлять минимум двумя осями;
* иметь механизм Pen Up / Pen Down;
* работать в определённой системе координат;
* принимать цифровое описание рисунка;
* преобразовывать его в последовательность движений;
* рисовать минимум несколько геометрических фигур;
* соблюдать границы рабочей области;
* иметь возможность остановить движение;
* корректно возвращаться в исходное состояние.

Минимальный pipeline:

**Drawing Data → Coordinates → Motion Controller → Motors → Paper**

AI для самой первой работающей версии вообще может отсутствовать.

Это нормально: сначала создаётся надёжный **Drawing Runtime**.

# Возможное развитие

## Level 2 — Shape Language

Создать небольшой собственный язык рисунков.

Например:

```text
LINE
CIRCLE
RECTANGLE
TRIANGLE
MOVE
PEN_UP
PEN_DOWN
```

Команда:

> `CIRCLE x=50 y=50 radius=20`

превращается в необходимые движения моторов.

Появляется промежуточный слой:

**Drawing Description → Drawing Engine → Coordinates**

Именно этот слой впоследствии сможет использовать AI.

---

## Level 3 — Natural Language

Подключить LLM.

Теперь пользователь пишет:

> «Нарисуй дом: квадрат, треугольная крыша, два окна и дверь».

LLM не управляет моторами.

Она генерирует структурированное описание:

```text
RECTANGLE(...)
TRIANGLE(...)
RECTANGLE(...)
RECTANGLE(...)
RECTANGLE(...)
```

Drawing Engine проверяет команды и только после этого преобразует их в координаты.

Получается:

**Natural Language → LLM → Drawing Plan → Validator → Drawing Engine → Robot**

Участник видит очень важную архитектурную границу:

> **AI генерирует план. Детерминированная система исполняет его.**

---

## Level 4 — Composition

Дать AI возможность самостоятельно компоновать сцену.

Например:

> «Нарисуй ночной город».

Система определяет:

**несколько зданий → окна → луна → звёзды**

и размещает элементы внутри рабочей области.

Здесь появляется новая проблема:

> **Как перевести семантическое описание в пространственную композицию?**

Участник начинает работать с координатами, масштабированием и ограничениями.

---

## Level 5 — Image to Drawing

Теперь на вход можно передать изображение.

Система преобразует его в упрощённое линейное представление:

**Image → Contours → Paths → Coordinates**

После чего робот воспроизводит линии на бумаге.

Например, пользователь загружает простой логотип или рисунок, а устройство создаёт его физическую версию.

Здесь AI уже необязательно является главным компонентом: часть задачи эффективнее решается обычными алгоритмами обработки изображений.

И это хороший урок:

> **Не каждую задачу внутри AI-проекта необходимо решать нейросетью.**

---

## Level 6 — AI Generated Drawing

Следующий шаг:

> «Нарисуй маленького робота, который держит цветок».

AI создаёт изображение или векторное представление.

Затем:

**Prompt → Generated Image → Simplification → Vectorization → Path Planning → Robot**

Теперь пользователь начинает с идеи и заканчивает реальным физическим рисунком.

---

## Level 7 — Drawing Styles

Добавить различные физические стили.

Например:

**Minimal**

**Geometric**

**Sketch**

**Single Line**

Для робота особенно интересен **Single Line**, когда изображение по возможности строится одной непрерывной линией.

Здесь возникает уже алгоритмическая задача:

> Как построить эффективный маршрут карандаша?

Чем меньше ненужных перемещений:

**Pen Up → Move → Pen Down**

тем быстрее работает устройство.

---

## Level 8 — Path Optimization

Оптимизировать движение.

Допустим, рисунок содержит 50 независимых линий.

В каком порядке их рисовать?

Плохой маршрут:

> робот постоянно перемещается через весь лист.

Хороший:

> соседние элементы выполняются последовательно.

Появляется:

**Drawing → Paths → Optimization → Execution**

Участник сталкивается уже с настоящей задачей планирования движения.

---

## Level 9 — Interactive Drawing

Добавить взаимодействие во время рисования.

Например:

> — Нарисуй робота.

Робот начинает работу.

Пользователь:

> — Добавь ему антенну.

Система должна учитывать уже существующий рисунок и добавить новый элемент.

Или:

> — Напиши снизу TAIL.

Получается уже не одноразовая генерация:

**Current Canvas + New Request → Updated Drawing Plan**

---

# Роль AI в проекте

Здесь особенно важно не продавать проект как:

> «ChatGPT управляет роботом».

Архитектура намного интереснее.

Условно:

```text
Human
  ↓
Natural Language
  ↓
AI
  ↓
Drawing Plan
  ↓
Validator
  ↓
Drawing Engine
  ↓
Path Planner
  ↓
Motion Controller
  ↓
Motors
  ↓
Physical Drawing
```

Каждый слой отвечает за своё.

**AI** понимает намерение.

**Drawing Engine** понимает рисунок.

**Path Planner** понимает траектории.

**Motion Controller** понимает механику.

**Моторы** выполняют движение.

Если LLM выдаёт:

> `x = 999999`

Validator должен отклонить такую команду, если координата находится за пределами рабочей области.

AI не определяет физические ограничения устройства.

# Потенциал развития в TAIL

AI Drawing Robot — прежде всего **витринный инженерный проект**.

Он очень хорошо подходит для:

* Demo Day;
* выставок;
* дней открытых дверей;
* стенда TAIL;
* технических мероприятий.

Потому что результат взаимодействия человек получает буквально в руки.

Посетитель говорит:

> «Нарисуй мне космического кота».

Через некоторое время робот выдаёт физический рисунок.

Его можно забрать.

Это создаёт совершенно другой эффект, чем ещё одна демонстрация AI на экране.

# Интеграция с POLY

В дальнейшем Drawing Robot можно предоставить как Tool.

Например:

> «POLY, нарисуй логотип TAIL».

POLY формирует задачу и передаёт её специализированной системе.

```text
POLY
  ↓
Drawing Tool
  ↓
Drawing Service
  ↓
Path Planner
  ↓
Drawing Robot
```

При этом POLY не должен знать, сколько шагов необходимо сделать конкретному двигателю.

Это ответственность самого Drawing Robot.

Связано с [[POLY - AI ассистент|POLY — AI ассистент]].

# Интеграция со Smart Demo Stand

А вот эта связка особенно интересна для выставки.

Посетитель подходит к **Smart Demo Stand**.

Стенд обнаруживает человека:

> «Хочешь получить рисунок от нашего AI-робота?»

Человек выбирает сценарий и описывает рисунок.

Дальше:

**Smart Demo Stand → AI Drawing Robot → Physical Drawing**

Получается уже единая интерактивная инсталляция из нескольких MiniProjects.

Связано с [[Smart Demo Stand - Интерактивный демонстрационный стенд|Smart Demo Stand]].

# Оборудование и инструменты

Для реализации могут понадобиться:

* Arduino / ESP32;
* два шаговых двигателя;
* драйверы двигателей;
* направляющие;
* ремни/шкивы или другой механизм движения;
* сервопривод для Pen Up / Pen Down;
* концевые выключатели;
* блок питания;
* провода;
* крепление карандаша/маркера;
* рабочая поверхность;
* детали корпуса.

Большую часть механических компонентов можно изготовить на 3D-принтере.

Для AI Levels понадобится компьютер или сервер, выполняющий более тяжёлую обработку.

Микроконтроллеру не нужно самостоятельно запускать LLM или генератор изображений.

# Критерии готовности

Проект считается завершённым, если:

* механизм стабильно двигается по двум осям;
* существует определённая рабочая область;
* реализован Pen Up / Pen Down;
* устройство способно выполнить homing;
* робот рисует несколько заранее определённых фигур;
* цифровое представление преобразуется в физический рисунок;
* некорректные координаты не исполняются;
* существует безопасная остановка;
* AI не получает прямого управления моторами;
* участник способен объяснить каждый этап от пользовательской команды до движения двигателя.

Для AI Level дополнительно:

* естественный язык преобразуется в структурированный Drawing Plan;
* план валидируется;
* разные формулировки способны приводить к корректным рисункам.

# Demo Day

На стенде лежат чистые карточки или небольшие листы бумаги.

Посетителю предлагают:

> **«Скажи, что нарисовать».**

Например:

> «Нарисуй маленького робота с флагом TAIL».

На экране можно показать процесс:

**UNDERSTANDING**

↓

**DRAWING PLAN**

↓

**PATH GENERATED**

↓

**DRAWING**

После этого механизм начинает двигаться.

Через некоторое время человек получает **физический результат работы системы**, который может забрать.

А рядом показывается архитектура:

**Human Idea → AI → Drawing Representation → Path Planner → Controller → Motors → Paper**

В этом и сила проекта: между фразой **«нарисуй робота»** и движением двух электромоторов студенту приходится построить целую инженерную систему.
